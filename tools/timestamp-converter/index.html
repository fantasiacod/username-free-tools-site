What is a Unix timestamp?

A Unix timestamp (also called Unix time, POSIX time, or epoch time) counts the number of seconds that have elapsed since midnight UTC on January 1, 1970 — the "Unix epoch" — ignoring leap seconds. It's a single integer that doesn't depend on time zone or calendar formatting, which is why databases, APIs, log files, and programming languages almost universally store dates internally as a Unix timestamp rather than a formatted string. Many systems (including JavaScript's own Date.now()) use milliseconds instead of seconds, so this tool auto-detects which one you've pasted based on how many digits it has, or you can set it manually.

When you'd use a timestamp converter

You'll run into raw Unix timestamps constantly while debugging: an API response with a created_at field that's just a long number, a log line stamped with epoch milliseconds, a JWT token's exp claim, or a database column storing dates as integers. This tool converts a timestamp into a readable local time, UTC time, ISO 8601 string, and a plain-English relative time ("3 hours ago") all at once, and works the other way too — pick a date and time and get back the exact Unix seconds and milliseconds, handy for building test data, API requests, or cron/scheduling logic that expects epoch time.
