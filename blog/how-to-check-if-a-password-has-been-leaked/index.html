How to Check If a Password Has Been Leaked (and What Makes One Actually Strong)

September 23, 2026

A password can look strong — long, random-looking, full of symbols — and still be worthless if it already sits in a stolen-data file being traded online. Length and character variety only protect you from someone guessing; they do nothing once a password has actually leaked in a breach. Here's what genuinely makes a password strong, how leaks happen in the first place, and a safe way to check if one of yours has already been exposed.

What makes a password strong (beyond length)

Length matters, but it's not the whole story. A strong password is unpredictable: truly random, not built from a pattern a computer can guess its way toward. Swapping letters for look-alike symbols ("P@ssw0rd!") barely helps — password-cracking tools have had these substitutions built in for years, so "P@ssw0rd!" is cracked about as fast as "Password". Real strength comes from randomness across a large character set (uppercase, lowercase, numbers and symbols together, not just one), and — just as important — uniqueness. A brilliant, random 20-character password is still a liability if you use the exact same one on ten different sites, because it only takes one of those ten getting breached to put the other nine at risk too.

How a password actually "leaks"

A leak almost never means someone guessed your password. It usually means a company you had an account with got hacked, and its entire user database — including passwords, sometimes stored badly (unhashed, or hashed with weak, outdated algorithms) — ended up copied and circulated. Once that data is out, attackers don't need to crack anything: they run "credential stuffing" attacks, automatically trying the same leaked email-and-password pairs against banks, email providers and social media, betting that people reuse passwords. That bet pays off constantly, which is exactly why password reuse — not weak individual passwords — is the single biggest risk most people carry.

How to check if a password has been leaked, safely

The well-known, privacy-respecting way to do this is the "Pwned Passwords" database run by Have I Been Pwned (haveibeenpwned.com), built from hundreds of millions of real passwords found in known breaches. The clever part is how it protects you while checking: your browser never sends the actual password. It hashes the password locally (SHA-1), sends only the first 5 characters of that hash to the API, and gets back every hash suffix in the world starting with those 5 characters — then checks locally whether your full hash is among them. This is called k-anonymity, and it means the service (or anyone watching the network request) never learns your actual password, only that a hash prefix was queried. If a password comes back as "seen" — even once — treat it as burned and stop using it anywhere, regardless of how long or complex it looks.

If a password has been leaked, do this

Change it immediately on the site it leaked from, and — this is the part people skip — on every other site where you used the same password or a close variant, since attackers try those combinations first. Turn on two-factor authentication (2FA) wherever it's offered, so a leaked password alone isn't enough to get in. And going forward, use a password manager: it generates a unique random password for every single site and remembers them for you, so reuse stops being a temptation at all. Generating a fresh, unique password for each account you change today is a good place to start.

Quick reference

  • Length helps against guessing, but reuse is what actually gets accounts broken into via credential stuffing.
  • Leetspeak substitutions (@ for a, 0 for o) barely slow down modern cracking tools — true randomness is what matters.
  • "Pwned Passwords" checks use k-anonymity: only a hash prefix is sent, never your actual password.
  • If a password shows up as leaked anywhere, change it everywhere you reused it, not just on the one site.
