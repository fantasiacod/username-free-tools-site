Why Is My JSON Invalid? Common Errors and How to Fix Them

September 11, 2026

"Unexpected token" is one of the least helpful error messages in programming — it tells you something is wrong without telling you what. The good news is that almost every broken JSON file fails for one of a small handful of reasons, and once you know what to look for, most are a five-second fix.

JSON's rules are stricter than JavaScript's

JSON looks like a JavaScript object literal, which is exactly why it trips people up — JavaScript itself is far more forgiving than the JSON spec. Code you can paste straight into a browser console often isn't valid JSON at all. Here are the mistakes that cause almost every "invalid JSON" error.

1. A trailing comma

This is by far the most common one. JavaScript allows a comma after the last item in an object or array; JSON does not.

{"name": "Alex", "age": 30,}

Delete the comma right before the closing } or ]. This happens constantly when you add a field to the end of an object and forget the old last line already had a comma, or delete a field and leave the comma dangling.

2. Single quotes instead of double quotes

JSON strings and keys must use double quotes ("). Single quotes ('), which JavaScript accepts fine, are not valid JSON.

{'name': 'Alex'}

Replace every single quote around a key or string value with a double quote. If the string itself contains a double quote, escape it as \".

3. Unquoted keys

In JavaScript you can write {name: "Alex"} and it works. In JSON, every key must be a quoted string, no exceptions.

{name: "Alex"}

Wrap every key in double quotes: {"name": "Alex"}.

4. Comments

JSON has no comment syntax at all — not //, not /* */. If a config file or API sample you copied includes explanatory comments, that alone makes it invalid JSON.

Delete every comment before parsing. If you need documentation alongside config data, that's usually a sign the file should be something other than plain JSON (like JSON5, YAML, or JSON with a separate README).

5. Unescaped special characters inside a string

A raw newline, tab, or unescaped double quote sitting inside a string value breaks the parser, because JSON strings must live on a single logical line with special characters written as escape sequences.

Use \n for a newline, \t for a tab, and \" for a double quote inside a string, instead of a literal line break or unescaped quote character.

6. Values JSON doesn't support

JSON only allows strings, numbers, objects, arrays, true, false and null as values. JavaScript-only values like undefined, a function, a Date object, or NaN are not valid JSON and will fail to parse.

Replace them with a JSON-safe equivalent — for example store a date as an ISO string like "2026-09-11" rather than a Date object, and use null instead of undefined.

7. A missing or mismatched bracket

Every { needs a matching }, and every [ needs a matching ]. This is easy to get wrong by hand in a deeply nested structure, and it's usually what's actually happening when the error points at the very end of the file.

Work from the innermost object or array outward and count brackets, or better, let a formatter do it — pretty-printed, correctly indented JSON makes an unclosed bracket visually obvious in a way a single unbroken line never will.
